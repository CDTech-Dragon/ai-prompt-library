# 产品合格证生成器

V1.0

## 项目概述

产品合格证生成器是一款基于前后端分离架构的 Web 应用，旨在为制造业企业提供高效、规范的产品合格证生成与管理解决方案。通过自动化数据录入、实时预览、一键打印和系统化数据存储功能，替代传统手动制作合格证的繁琐流程，提升工作效率与数据规范性，支持产品质量追溯与数据统计分析。

## 核心功能特性

### 1. 产品信息输入

- 支持录入产品型号、数量、箱号、总箱数、订单号、机器编号等关键信息；
- 自动生成当前日期并填充至 “生产日期” 字段，支持手动修改；
- 二维码内容支持自定义输入，或自动拼接 “产品型号 - 订单号 - 箱号 - 生产日期” 组合信息；
- 表单关键字段非空校验、格式校验（如数量为数字、箱号格式规范），实时提示错误信息。

### 2. 实时预览

- 输入数据后即时更新合格证预览效果，支持弹窗放大预览；
- 预览区按实际打印尺寸比例展示，包含产品信息、二维码、落款等完整元素；
- 数据修改后预览同步刷新，无需手动触发，便于快速调整确认。

### 3. 打印功能

- 支持一键触发浏览器打印功能，适配 A4、自定义标签等常见合格证尺寸；
- 打印前自动校验数据完整性，数据不完整时提示补充录入；
- 打印完成后自动将合格证数据保存至数据库，无需额外操作。

### 4. 数据管理

- 自动将所有生成的合格证数据持久化存储至 MySQL 数据库，支持数据增删改查；
- 前端支持历史数据查询，默认展示最近 30 天记录，支持按产品型号、订单号、生产日期、箱号筛选；
- 筛选结果分页展示，支持按创建时间倒序 / 正序排列，优先展示最新数据；
- 支持查看历史合格证详情，可重新打印或编辑修改。

### 5. 二维码生成

- 基于 vue-qrcode 库生成高清二维码，支持正常扫描识别；
- 二维码内容实时响应输入变化，自定义内容或自动组合内容切换时即时重新生成；
- 预览区二维码支持放大查看，确保打印后扫描清晰度。

## 使用说明

### 1. 生成合格证

1. 访问前端应用（默认地址：[http://localhost:5173](http://localhost:5173/)）；
2. 在输入表单中填写产品相关信息，系统自动填充生产日期；
3. 自定义二维码内容或使用默认组合内容；
4. 查看实时预览效果，确认无误后点击 “打印” 按钮；
5. 在打印对话框中配置打印机参数（纸张尺寸、打印份数等），完成打印；
6. 打印后数据自动保存至数据库，可在 “历史数据” 模块查看。

### 2. 历史数据查询与管理

1. 点击前端 “历史数据” 菜单，进入数据列表页；
2. 使用筛选条件（产品型号、订单号、生产日期、箱号）查找目标数据；
3. 点击列表项可查看详情，支持重新打印或编辑修改；
4. 编辑修改后点击 “保存” 按钮，更新数据库记录。

## API 接口说明

- **URL**: `/api/certificates`
- **Method**: POST
- **Request Body**:

json

```json
{

  "model2": "产品型号2",
  "quantity": "数量",
  "boxNo": "箱号",

  "moNo": "订单号",

  "productionDate": "生产日期",
```

### 查询合格证数据

- **URL**: `/api/certificates`
- **Method**: GET
- Query Parameters:
  - `model`: 产品型号（模糊查询）
  - `moNo`: 订单号（模糊查询）
  - `productionDate`: 生产日期
  - `boxNo`: 箱号（精确查询）
  - `pageNum`: 页码（默认 1）
  - `pageSize`: 每页条数（默认 20）
- **Response**:

```json
{
  "code": 200,
  "message": "查询成功",
  "data": {
    "total": 100,
    "list": [
      {
        "id": 1,
        "model": "产品型号",
        "boxNo": "箱号",

  }
}
```

## 开发说明

### 前端开发规范

- 采用 Vue 3 Composition API 组织业务逻辑，替代 Options API；
- 组件采用单文件组件（SFC）格式，按功能模块划分组件目录；
- 使用 TypeScript 定义接口类型、组件 Props、函数参数，确保类型安全；
- UI 组件优先使用 Element Plus，自定义样式统一维护在全局样式文件；
- API 请求统一封装在`services`目录，支持请求 / 响应拦截、异常统一处理。

### 后端开发规范

- 采用 MVC 架构模式，分离路由（routes）、控制器（controllers）、数据模型（models）；
- 使用 Sequelize ORM 操作数据库，避免直接编写 SQL 语句，提升代码可维护性；
- 接口返回统一格式（code、message、data），便于前端统一处理；
- 所有业务逻辑在控制器中实现，数据模型仅负责数据表映射与关联；
- 异常处理：捕获数据库操作、接口请求等异常，返回友好错误提示。

## 注意事项

1. 确保 MySQL 数据库服务正常运行，且后端配置的数据库连接信息正确；
2. 前后端默认端口分别为 5173（前端）和 3000（后端），若端口被占用，需修改配置文件；
3. 打印功能依赖浏览器打印 API，建议使用 Chrome 浏览器以获得最佳兼容性；
4. 二维码生成需确保内容不超过字符限制，避免影响扫描识别；
5. 生产环境部署时，需配置 HTTPS 协议，确保数据传输安全。
