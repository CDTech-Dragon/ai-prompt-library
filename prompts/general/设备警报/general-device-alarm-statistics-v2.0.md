# 设备报警统计提示词 - v2.0.0
> 简短描述：用于生成设备报警统计相关的分析和解决方案，支持多种数据源和前端展示需求

#### 1. 基础信息
| 字段         | 内容                          |
|--------------|-------------------------------|
| ID           | prompt-general-device-alarm-001 |
| 适用模型     | GPT-4, Claude 3, 通义千问     |
| 难度等级     | 进阶                          |
| 创建时间     | 2025-11-20                    |
| 最后更新时间 | 2026-01-04                    |
| 作者         | prompt-library-contributors   |

#### 2. 核心用途
详细说明：
- 该提示词用于分析生产线设备异常报警问题，生成报警统计方案
- 适用于制造业设备管理、生产线优化、品质管控等场景
- 相比普通提示词，包含了完整的需求分析、数据来源和功能要求，便于生成更精准的解决方案

#### 3. 提示词正文
> 遵循 ROLE-TASK-CONSTRAINT-OUTPUT 框架

### 角色
你是资深设备管理系统架构师，擅长制造业设备数据采集和分析系统设计。

### 任务
请根据以下需求，设计一个设备报警统计系统的解决方案，包括数据采集、处理、存储和前端展示。

### 约束条件
1. 支持多种数据源：设备运行日志、IOT数据接口、客户端工具采集数据
2. 前端展示需包含指定的数据列和筛选功能
3. 支持报警规则配置和自动推送功能
4. 客户端需支持自动重启和静默运行
5. 需考虑多地域、多车间、多线别的设备管理

### 输出格式
```markdown
# 设备报警统计系统解决方案

## 1. 问题分析
- **现象**：生产线设备异常报警频繁，需人为介入消除，影响生产效率和车间环境
- **原因**：电、气动异常；产品检测报警；DUT位置异常；DUT超时等

## 2. 系统设计

### 2.1 数据采集层
- **设备日志**：HYT通设备运行异常日志以指定文件夹方式存储
- **IOT数据**：从.130的alarms和devices表获取IOT灯数据
- **客户端采集**：通过客户端工具获取每次异常类型、发生时间和触发标志

### 2.2 数据处理层
- 解析log日志文件，通过MES接口回馈数据到指定数据表
- 支持单Y轴和双Y轴设备的数据处理
- 实现数据合并和分析，支持多数据源关联

### 2.3 数据存储层
- 基于K3资产库：smt_assets_new（深圳、湖南各有数据表）
- 重启信息记录表：pcmonitor.alarms与pcmonitor.devices（.130数据表）
- 问题提报表：关联百川MES改善模块

### 2.4 前端展示层
- **数据列**：序号、机台编号、责任人、地域、车间、线别、机型、生产数量、报警最长时长、报警次数、问题条、落实情况、更新时间
- **筛选功能**：车间、线别固定下拉，其他字段支持模糊查找
- **报警规则**：小时次数（6次）、24H次数（20次），仅管理员可见
- **排序规则**：默认按报警次数降序排列
- **详情展示**：双击报警次数可查看具体报警时间、原因、分析和改善方向

### 2.5 系统功能
- 每日超出警报规则的前TOP3自动推送至百川MES改善模块
- 问题排名靠前的工程师及部门长在首页消息通知中警示呈现
- 支持一键查询无报警数据的设备

## 3. 技术实现
- 客户端支持自动重启和静默运行
- 后端以进程或可视化托盘图标方式最小化运行
- 支持多地域、多车间、多线别的设备管理
- 前端支持响应式设计，适配不同设备

## 4. 设备范围
基于K3资产库中的以下设备类型：
- 镭雕机
- 平行移载
- 印刷机
- 分板机
- 全自动测试设备
- AOI
- SPI

## 5. 预期效果
- 减少人为介入消除警报的次数
- 提高生产效率和产品品质
- 改善车间环境
- 实现设备异常的自动监控和预警
- 支持设备问题的追溯和分析
```

#### 4. 使用示例

##### 输入场景
请根据以上提示词，设计一个设备报警统计系统的详细方案。

5. 需考虑多地域数据的同步和一致性
