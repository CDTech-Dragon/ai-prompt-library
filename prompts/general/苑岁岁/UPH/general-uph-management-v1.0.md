#### 3. 提示词正文
> 遵循 ROLE-TASK-CONSTRAINT-OUTPUT 框架

### 角色
你是资深生产管理系统架构师，擅长制造业标准工时管理系统设计和实现。

### 任务
请根据以下需求，设计ST_UPH标准工时管理系统的解决方案，包括数据结构设计、功能实现和技术选型。

### 约束条件
1. 无客户端单独运行终端，系统需基于现有EMS平台开发
2. 需建立基于方案、测试流程、产品类别的标准基础资料库
3. 支持多表管理（芯片方案表、通用工艺表、设备工艺表、UPH主表）
4. 支持数据的增、删、改、查和批量导入导出功能
5. 权限控制：只有系统管理员和指定PIE工程师（李光、曹宝平、向学、舒兴洪）有维护权限
6. UI风格需与EMS中其他版块保持一致，使用淡蓝色科技背景

### 输出格式
```markdown
# ST_UPH标准工时管理系统解决方案

## 1. 问题分析
- **现象**：标准不统一、人为实际生产数据作为标准工时标准、不同方案设备间标准差异巨大
- **原因**：欠缺建立基于方案、测试流程、产品类别的标准基础资料库，排产时人为干扰因素大

## 2. 系统设计

### 2.1 数据结构设计

#### 基础表1：芯片方案表
| 字段名 | 字段说明 |
|--------|----------|
| id_seq | ID序号 |
| chip_scheme | 芯片方案 |
| test_frequency | 测试频点 |
| test_item | 测试项目 |
| test_duration | 测试时长 |
| remark | 备注 |

#### 基础表2：通用工艺表
| 字段名 | 字段说明 |
|--------|----------|
| id_seq | ID序号 |
| test_item | 过程项目 |
| test_duration | 时长 |
| remark | 备注 |

#### 基础表3：设备工艺表
| 字段名 | 字段说明 |
|--------|----------|
| id_seq | ID序号 |
| test_item | 过程项目 |
| test_duration | 时长 |
| remark | 备注 |

#### 主表：UPH表
| 字段名 | 字段说明 |
|--------|----------|
| id_seq | ID序号 |
| product | 产品 |
| test_step | 测试步骤 |
| test_item | 测试项目 |
| test_duration | 时长 |
| remark | 备注 |

### 2.2 功能实现

#### 核心功能
1. **数据管理**：支持基础表1-3和主表的增、删、改、查功能
2. **批量操作**：支持批量数据导入、导出功能
3. **数据关联**：主表与基础表的数据关联和自动计算
4. **权限控制**：基于角色的权限管理

#### 前端展示
- **主界面数据列**：序号、产品、测试步骤、测试项目、时长
- **筛选功能**：按芯片方案、测试项目、时长模糊查找

### 2.3 逻辑功能
1. 基础表1-3单独维护基础资料库清单
2. 基础表1的芯片方案是与主表映射的主要关键
3. 主表选择产品型号匹配到对应的芯片方案后，自动带入测试步骤和时长
4. 基础表2-3的通用项目形成可勾选清单，供主表选择
5. 自动计算测试项目的总时长功能

### 2.4 技术实现
- 基于现有EMS平台开发，无单独客户端终端
- 使用与EMS一致的CSS样式和设计风格
- 支持淡蓝色科技背景

## 3. 部署与维护
- 全新数据源，按数据来源要求建立数据表
- 定期维护基础资料库，确保数据准确性
- 支持权限管理和操作审计

## 4. 预期效果
- 建立统一的标准工时基础资料库
- 减少排产时的人为干扰因素
- 实现标准的真实标准化
- 提高生产计划的准确性和可靠性
```
