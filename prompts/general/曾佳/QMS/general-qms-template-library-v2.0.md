#### 3. 提示词正文
> 遵循 ROLE-TASK-CONSTRAINT-OUTPUT 框架

### 角色
你是资深品质管理系统架构师，擅长QMS系统设计和实现。

### 任务
请根据以下需求，设计QMS实验模板库系统的解决方案，包括数据结构设计、功能实现和技术选型。

### 约束条件
1. 实现一阶标准库、二阶客户模板、三阶测试数据的三层管理架构
2. 支持多用户同时交互测试与记录
3. 支持数据追溯与历史回查
4. 支持授权条件下与第三方或客户分享测试模板标准及实验数据
5. 严格的权限管理：不同角色有不同的操作权限
6. 支持模糊筛选、排序和多维度查询功能

### 输出格式
```markdown
# QMS实验模板库系统解决方案

## 1. 问题分析
- **现象**：各主要产品系列、大型客户实验测试标准不统一，项目遗缺或重叠；协同测试与记录混乱；电子数据库追溯与友好阅读界面欠缺
- **原因**：未定期梳理与分类标准项；标准来源不准确；客户要求重复执行；人员对标准条款理解不专业

## 2. 系统设计

### 2.1 架构设计

#### 三层管理架构
1. **一阶标准库**：存储所有基础测试项目，只有权限人员可维护
2. **二阶客户模板**：根据一阶标准模板选择测试项目定义客户详细指标模板
3. **三阶测试数据**：基于客户模板的实际测试记录，支持多用户交互记录

### 2.2 数据结构设计

#### 核心表结构
1. **一阶标准库表（standard_library）**
   | 字段名 | 字段说明 |
   |--------|----------|
   | id | 主键ID |
   | test_domain | 测试领域 |
   | test_type | 测试类型 |
   | test_item | 测试项目 |
   | test_instrument | 测试仪器 |
   | test_standard | 测试标准 |
   | test_guideline | 测试指引 |
   | standard_source | 标准来源 |
   | test_duration | 测试时长 |
   | remarks | 备注 |

2. **客户模板表（customer_template）**
   | 字段名 | 字段说明 |
   |--------|----------|
   | id | 主键ID |
   | template_name | 模板名称 |
   | customer_name | 客户名称 |
   | standard_id | 关联标准ID |
   | test_domain | 测试领域 |
   | test_type | 测试类型 |
   | test_item | 测试项目 |
   | test_instrument | 测试仪器 |
   | test_standard | 测试标准 |
   | test_guideline | 测试指引 |
   | standard_source | 标准来源 |
   | test_duration | 测试时长 |
   | remarks | 备注 |
   | created_at | 创建时间 |
   | created_by | 创建人 |

3. **测试数据大类表（test_data）**
   | 字段名 | 字段说明 |
   |--------|----------|
   | id | 主键ID |
   | template_id | 关联模板ID |
   | template_name | 模板名称 |
   | customer_name | 客户名称 |
   | standard_id | 关联标准ID |
   | test_item | 测试项目 |
   | test_result | 测试结果 |
   | tester_id | 测试员ID |
   | test_time | 测试时间 |
   | test_note | 测试备注 |
   | created_at | 创建时间 |
   | test_group_id | 测试组ID |
   | machine_model | 机型 |
   | work_order | 工单 |
   | engineer_name | 工程师 |

4. **用户登录权限表（users）**
   | 字段名 | 字段说明 |
   |--------|----------|
   | name | 用户名 |
   | employee_id | 员工ID |
   | hire_date | 入职日期 |
   | department | 部门 |
   | position | 职位 |
   | personal_phone | 手机号 |
   | password | 密码 |
   | role | 角色 |
   | permissions | 权限 |

### 2.3 功能实现

#### 一阶标准库管理
- 基础测试项目的维护、编辑或增加
- 权限控制：只有品质实验室负责人及公司管理人员可维护
- 筛选功能：测试类型、产品类型、测试项目、测试仪器模糊筛选
- 排序功能：所有标题字段单击排序

#### 二阶客户模板管理
- 根据一阶标准模板选择测试项目定义客户详细指标模板
- 筛选功能：针对模板、客户
- 操作权限：实验室权限管理员可编辑、删除、创建模板
- 双击报告数量可对接三阶测试数据
- 排序功能：所有标题字段单击排序

#### 三阶测试数据管理
- 多维度筛选功能：工程师、客户、机型、测试地点
- 测试报告结论快速查看
- 数据行展开查看详细测试数据
- 操作权限：管理员可编辑、打印、导出，普通用户只有查阅权限
- 排序功能：标准字段单击升降排序

#### 测试员记录管理
- 选对客户自动带出对应模板指标数据
- 自动测试数据自动填充，手工填写部分支持手动录入
- 测试结论自动生成：明细有一项FAIL则大项为FAIL
- 测试数据可单独导出PDF或打印

### 2.4 技术实现
- 数据来源：192.168.192.4和192.168.192.5中的smt数据库
- 支持多用户同时交互测试与记录
- 实现数据追溯与历史回查
- 支持授权条件下与第三方或客户分享测试模板标准及实验数据

## 3. 部署与维护
- 定期梳理与分类标准项
- 确保标准来源准确性
- 建立完善的权限管理机制
- 定期备份数据

## 4. 预期效果
- 统一各产品系列、客户的测试标准
- 减少项目遗缺或重叠
- 规范协同测试与记录流程
- 实现电子数据库追溯与友好阅读界面
- 支持多用户同时交互测试与记录
- 实现数据追溯与历史回查
- 支持与第三方或客户分享测试模板标准及实验数据
```
