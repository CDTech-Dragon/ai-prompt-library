# 提示词编写指南

## 核心原则
1. **清晰性**：明确角色、任务、约束，避免模糊表述；
2. **可复用性**：通用部分固化，个性化部分用占位符标注；
3. **适配性**：注明适用模型，跨模型差异需补充说明；
4. **可验证性**：提供真实使用示例，确保效果可复现。

## 框架推荐

### ROLE-TASK-CONSTRAINT-OUTPUT 框架
- **ROLE（角色）**：定义AI的身份（如「资深SQL工程师」「产品经理」）；
- **TASK（任务）**：明确要完成的核心目标（避免歧义）；
- **CONSTRAINT（约束）**：技术/格式/风格约束；
- **OUTPUT（输出）**：指定输出结构/格式。

### 示例
```
角色：你是资深 MySQL 工程师，熟悉电商业务场景

任务：编写 SQL 语句，统计近 7 天每个商品的下单量（去重）

约束：
1. 兼容 MySQL 8.0+
2. 输出包含注释，解释分组 / 过滤逻辑
3. 处理 NULL 值（下单量为 0 的商品也要显示）

输出格式：
```sql

-- 近7天商品下单量统计
SELECT 
  goods_id,
  COUNT(DISTINCT order_id) AS order_count
FROM order_table
WHERE create_time >= DATE_SUB(NOW(), INTERVAL 7 DAY)
GROUP BY goods_id
ORDER BY order_count DESC;
```

## 避坑指南
1. 避免使用「帮我写一个SQL」这类模糊表述，需明确场景；
2. SQL类提示词需注明数据库类型（MySQL/PostgreSQL/Oracle）；
3. AI绘画提示词需区分模型（Midjourney/Stable Diffusion），标注权重/参数；
4. 不要包含敏感信息（如手机号、密钥），用占位符替代；
5. 核心逻辑需详细说明，避免过于简略导致AI误解；
6. 输出格式需明确，避免AI返回不符合预期的格式。

## 编写流程
1. 确定提示词的核心用途和适用场景；
2. 选择合适的框架（推荐ROLE-TASK-CONSTRAINT-OUTPUT）；
3. 编写提示词正文，确保清晰、完整；
4. 添加使用示例，验证效果；
5. 补充注意事项和变更日志；
6. 按照命名规则命名文件并放入对应目录。

## 格式检查清单
- [ ] 包含所有必填模块：基础信息、核心用途、提示词正文、使用示例
- [ ] 遵循文件命名规则
- [ ] 代码块标注了语言类型
- [ ] 包含适用模型说明
- [ ] 提供了真实使用示例
- [ ] 输出格式明确
- [ ] 无敏感信息

## 跨模型适配指南
- **GPT系列**：支持复杂逻辑，可使用更详细的约束；
- **Claude系列**：擅长长文本处理，可提供更多上下文；
- **通义千问**：中文效果较好，英文提示词需调整；
- **Midjourney**：需使用特定关键词和权重格式；
- **Stable Diffusion**：支持更精细的参数控制。

## 示例提示词模板

### 通用文本总结提示词
```
角色：你是专业文本分析师，擅长提取核心信息

任务：总结以下文本的核心观点，要求结构清晰、要点明确

约束：
1. 字数控制在100-200字之间
2. 保留原文的关键数据和结论
3. 避免添加个人观点
4. 使用列表格式输出

输入文本：
[待总结的文本内容]

输出格式：
```markdown
# 核心观点总结

1. [观点1]
2. [观点2]
3. [观点3]
```

### SQL查询优化提示词
```
角色：你是资深数据库优化工程师，熟悉MySQL和PostgreSQL

任务：优化以下SQL查询语句，提高执行效率

约束：
1. 兼容MySQL 8.0+和PostgreSQL 13+
2. 输出优化前后的语句对比
3. 解释优化原理
4. 包含执行计划分析

输入SQL：
[待优化的SQL语句]

输出格式：
```markdown
# SQL查询优化报告

## 优化前
```sql
[原始SQL]
```

## 优化后
```sql
[优化后的SQL]
```

## 优化原理
1. [原理1]
2. [原理2]
3. [原理3]

## 执行计划分析
- 优化前：[执行计划描述]
- 优化后：[执行计划描述]
```
