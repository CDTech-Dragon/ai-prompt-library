# 常见问题

## 使用类

### Q1：提示词在不同模型中效果不一致怎么办？
**A1**：参考提示词文件中的「注意事项」，不同模型的适配规则已标注；若未标注，可提Issue补充。建议针对不同模型微调提示词，特别是输出格式部分。

### Q2：如何快速找到所需的提示词？
**A2**：可通过README的「快速导航」进入分类，或使用GitHub的仓库搜索功能（快捷键`t`）。也可以根据目录结构按场景查找，如代码相关提示词在`prompts/code/`目录下。

### Q3：提示词可以直接使用吗？需要修改哪些部分？
**A3**：大部分提示词可以直接使用，只需修改占位符部分（如`[表名]`、`[待总结文本]`等）。建议先阅读「使用示例」了解具体用法。

### Q4：如何验证提示词的效果？
**A4**：可参考提示词文件中的「使用示例」，使用相同的输入测试不同模型。也可以自行设计测试用例，验证输出是否符合预期。

### Q5：提示词太长怎么办？可以简化吗？
**A5**：核心框架（ROLE-TASK-CONSTRAINT-OUTPUT）必须保留，其他部分可根据需求简化。建议先使用完整版本验证效果，再逐步简化。

## 贡献类

### Q6：提交的PR被驳回了怎么办？
**A6**：查看PR评论中的驳回原因，按规范调整后重新提交即可；若有疑问可直接回复评论交流。常见驳回原因包括：格式不符合要求、缺少核心模块、示例不真实等。

### Q7：新增的提示词场景没有对应分类怎么办？
**A7**：先提Issue说明场景，维护者确认后会创建新分类，再按新分类提交。也可以暂时放在`prompts/general/`目录下，由维护者后续调整。

### Q8：如何成为仓库的维护者？
**A8**：长期积极贡献优质提示词、参与Issue讨论、帮助审核PR的贡献者，可申请成为维护者。请直接联系仓库所有者或在Discussions中提出申请。

### Q9：可以修改已有提示词吗？
**A9**：可以，若发现提示词存在错误或可以优化，可提交PR修改。修改时需遵循以下规则：
1. 保持核心功能不变；
2. 更新版本号（如v1.0.0 → v1.0.1）；
3. 在变更日志中说明修改内容；
4. 提供测试示例验证修改效果。

### Q10：提示词的版权如何处理？
**A10**：提交的提示词需为原创，或基于MIT协议复用的内容。贡献的内容将默认采用仓库的MIT许可证（见LICENSE文件），允许商用和修改，但需注明来源。

## 技术类

### Q11：如何编写高效的提示词？
**A11**：遵循以下原则：
1. 明确角色和任务；
2. 添加具体约束条件；
3. 明确输出格式；
4. 提供示例；
5. 避免模糊表述。

### Q12：什么是「语义化版本」？如何正确使用？
**A12**：语义化版本格式为`主版本.次版本.修订号`：
- 主版本（Major）：不兼容的API变更；
- 次版本（Minor）：向下兼容的功能性新增；
- 修订号（Patch）：向下兼容的问题修正。

例如：v1.0.0 → v1.1.0（新增功能） → v1.1.1（修复bug） → v2.0.0（重构API）。

### Q13：如何处理提示词中的敏感信息？
**A13**：禁止在提示词中包含真实的敏感信息，如手机号、邮箱、密钥等。建议使用占位符替代，如`[手机号]`、`[API密钥]`等。

### Q14：提示词的文件命名规则是什么？
**A14**：格式为`[分类]-[核心用途]-v[版本号].md`（全部小写，连字符分隔）。例如：
- 通用文本总结：`general-text-summary-v1.0.md`
- SQL筛选NULL值：`code-sql-null-filter-v1.0.md`
- Python代码调试：`code-python-debug-v1.0.md`

### Q15：如何添加新的提示词分类？
**A15**：先提Issue说明新分类的用途和包含的场景，经维护者确认后，在`prompts/`目录下创建新的子目录，并更新README.md中的快速导航。

## 其他

### Q16：可以商用仓库中的提示词吗？
**A16**：可以，本仓库采用MIT许可证，商用时注明来源即可。建议在产品文档或致谢中提及本仓库。

### Q17：如何报告提示词中的错误？
**A17**：可通过以下方式报告：
1. 在GitHub上提Issue，描述错误现象和复现步骤；
2. 提交PR直接修复错误；
3. 在Discussions中讨论。

### Q18：仓库会定期更新吗？
**A18**：是的，仓库会定期更新，每周至少更新一次。更新内容包括：新增提示词、修复错误、优化现有提示词等。可关注`docs/changelog.md`查看更新日志。

### Q19：如何获取仓库的最新动态？
**A19**：可通过以下方式：
1. Star或Watch仓库，接收GitHub通知；
2. 关注仓库的Releases页面；
3. 定期查看`docs/changelog.md`文件。

### Q20：可以在其他平台分享仓库中的提示词吗？
**A20**：可以，但需注明来源（包含仓库链接和作者信息），并遵循MIT许可证的要求。建议在分享时附上原始文件链接，方便他人查看最新版本。
